# 場域災害偵測系統 簡要說明

## 一、目的

在沒有網路基礎建設的現場，用一般手機當攝影機，由現場的 Jetson Orin Nano 以 AI 即時判讀畫面有無災害徵兆（火、煙、淹水、人員倒地等），
分成「一般／警告／嚴重」三級，再透過 OneWeb 低軌衛星上網把判讀結果、縮圖與嚴重事件影像傳回地面站；地面站可反向下指令與通知。
沒有衛星上網時可改用自建的 DVB-S2 無線鏈路（USRP），整條路徑就不依賴任何網路基礎建設。

## 二、災害偵測流程

```
手機瀏覽器（相機頁） ──Wi-Fi 熱點──▶ Jetson Orin Nano                                  地面站電腦
  每秒約 4 張 JPEG                     │ 每 5 秒輪流取一支手機的最新影格                    │
                                      ├─ ① YOLO26s（TensorRT）：找出人、車、物件、位置（數十毫秒）
                                      ├─ ② Qwen3-VL 2B（Ollama）：看圖＋YOLO 清單，寫一句描述並判等級（約 5 秒）
                                      ├─ ③ 融合：取 VLM 判定與 YOLO 規則中較嚴重者 → 一般／警告／嚴重
                                      └─ ④ 報告（JSON）經 OneWeb（TCP）──────────────────────▶ 儀表板、SQLite、CSV
                                         嚴重時附上畫了偵測框的影像；被選手機另傳即時縮圖
                                      ◀──────────── 同一條連線回送：開始/停止偵測、選手機、調參數、文字通知（有 ACK 重送）
```

1. **影像來源**：手機不必裝 App，連上 Jetson 的 Wi-Fi 熱點後用瀏覽器開相機頁，輸入名稱即開始上傳；多支手機同時接入，Jetson 輪流辨識。
2. **物件偵測（YOLO26s）**：TensorRT FP16 引擎，每張數十毫秒，產生物件類別、信心、位置；可換成自行訓練的火／煙／倒地模型，並設定「偵測到即升級」規則。
3. **場景判讀（Qwen3-VL 2B）**：視覺語言模型在 Jetson 本機執行，依設定檔中的三級準則寫出中文描述並判定等級；YOLO 的偵測清單一併放進提示，補強小物件與數量判斷。
4. **融合與回報**：最終等級取兩者較嚴重者（寧可多報）；每筆報告含手機、時間、等級、描述、偵測清單、耗時；嚴重事件附影像（最長邊 640 px、上限 60 kB；TCP 可靠不必重送，DVB-S2 時重送兩次）。
5. **地面站**：收報告、存資料庫、顯示狀態橫幅／時間軸／紀錄／嚴重事件影像；可選看任一支手機的即時縮圖、開始或停止辨識、調整縮圖與 VLM 解析度、送文字通知到現場（手機與 Jetson 螢幕跳出）。

## 三、硬體架構

完整架構圖（Nano 端／PC 端分欄）：[docs/架構圖_oneweb.svg](docs/架構圖_oneweb.svg)（OneWeb 版）、[docs/架構圖.svg](docs/架構圖.svg)（DVB-S2 備用鏈路版），同目錄有 PNG 版可直接貼投影片。

```
             現場                                                              地面站
┌──────────────────────────────────┐      OneWeb 衛星 + 網際網路       ┌──────────────────────────────────┐
│ 手機 ×N ─Wi-Fi(5 GHz)─▶ Jetson   │   一條 TCP 連線（Nano 主動連）   │ 路由器（對外 123.193.37.73）       │
│  Orin Nano 8 GB                  │ ──────────────────────────────▶ │   TCP 6767 轉發 → 筆電            │
│  ├ YOLO + VLM（GPU）             │   報告、縮圖、嚴重影像、心跳      │  儀表板 http://localhost:8080     │
│  └ RJ45 ─ OneWeb 使用者終端      │ ◀────────────────────────────── │  SQLite／CSV／影像存檔            │
│     （CGNAT 後面，不能被連入）    │   指令、設定、通知（同一連線回送）│                                  │
└──────────────────────────────────┘                                  └──────────────────────────────────┘
```

| 元件 | 規格與角色 |
|---|---|
| Jetson Orin Nano 8 GB（JetPack 7.2.1） | 現場節點：Wi-Fi 熱點（10.42.0.1）、YOLO＋VLM 推論（GPU）、對地面站的 TCP 連線。記憶體是最緊的資源（模型約 5 GB） |
| OneWeb 使用者終端 | 低軌衛星上網，乙太網路接 Nano；往返延遲實測約 300 ms。終端在電信業者 NAT 後面，所以連線一律由 Nano 發起 |
| 地面站電腦＋路由器 | Ubuntu 筆電跑地面站程式與儀表板，不做 AI；路由器把 TCP 6767 轉發到筆電，讓 Nano 從網際網路連進來 |
| 手機 | 任何有瀏覽器的手機，當攝影機 |
| （備用）USRP B210 ×2＋天線 ×4 | 自建 DVB-S2 無線鏈路：數據機完整實作在 B210 的 FPGA 裡（自製 image：BCH＋LDPC、成幀、RRC、同步、AGC、FLL／PLL），下行 1000 MHz 8PSK 2/3、上行 1050 MHz QPSK 1/2，同一房間 Es/N0 約 19 dB |

**網路鏈路參數**：一條 TCP 連線，Nano → 地面站 `123.193.37.73:6767`；心跳每 2 秒（順便維持 NAT 映射），送出 20 秒沒 ACK 判定斷線、3 秒後重連。
本系統流量通常低於 0.1 Mbit/s（縮圖每秒 1 張約 8 kB、嚴重影像最多 60 kB），遠低於 OneWeb 終端的上傳頻寬。
截圖到地面站顯示約 6–8 秒（主要是 VLM 推論），縮圖延遲約 0.4–0.7 秒。

**實測路徑（2026-10-27，Nano 用 ping 遞增 TTL 逐跳量）**：共 20 跳、RTT 約 300 ms。
OneWeb 終端 192.168.100.1 → 衛星（不回應）→ OneWeb 閘道 10.82.250.193（約 120 ms）→ 中華電信國際閘道 TWGate（AS9505，175.41.63.126/125）→ 洛杉磯 PoP 203.78.187.182（跳到約 260 ms）
→ Arelion（AS1299）×4 → PCCW Global（AS3491）×2 → 台灣固網（AS9924，60.199.x）×4 → 凱擘 kbro（AS38841，10.4.21.x／10.2.6.18）→ 路由器對外 123.193.37.73 → 192.168.0.1 → 電腦 192.168.0.80。
衛星段只佔約 120 ms，其餘是 OneWeb 落地網路與家用寬頻之間沒有本地互連、繞經美國西岸的國際骨幹。Nano 的對外 IP 175.111.235.59 屬於中華電信國際閘道。

**軟體層次**（兩端相同）：應用程式 ⇄ `common/link.py`（tcp 模式）⇄ TCP ⇄ 網際網路。
訊息以 MPEG-TS 分段並附 CRC32 寫入 TCP 位元流，地面站對每條連線各用一個解多工器；指令與通知靠應用層 ACK 重送，嚴重事件影像以 (node, boot, seq) 去重。
改回 DVB-S2 時只需把兩邊 `link.mode` 改為 `fpga`：應用程式 ⇄ 本機 UDP ⇄ `dvbs2_b210` ⇄ USB ⇄ B210 FPGA 數據機 ⇄ 射頻。

## 四、擴充方向

- 多台現場節點：每台 Jetson 有 `node_id`，全部連到地面站同一個埠，地面站依節點區分（儀表板的即時狀態目前仍以單一節點呈現）。DVB-S2 備用鏈路時每節點要配一台地面站 USRP。
- 不依賴路由器轉發：兩邊裝 Tailscale，Nano 連地面站的 100.x.x.x，同時可從任何地方 SSH 進現場的 Nano 維護。
- 專用模型：收集場域影像訓練 YOLO（火、煙、倒地、未戴安全帽），搭配偵測規則可在 VLM 之前直接觸發嚴重等級。
- DVB-S2 備用鏈路更長距離：提高符號率或換高增益天線；目前參數在同一房間有約 12 dB 餘裕。
