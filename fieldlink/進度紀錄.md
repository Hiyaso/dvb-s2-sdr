# 場域監測系統（fieldlink）進度紀錄

最後更新：2026-10-27

## 1. 專案目標

多支手機當攝影機，透過 Jetson Orin Nano 的 Wi-Fi 熱點傳送即時影像。Jetson 每 5 秒輪流取一支手機的影格，用 YOLO 加 VLM 判讀場域狀況並分成一般、警告、嚴重三級，再經 OneWeb 衛星上網（2026-10-27 起；之前是 USRP 的 DVB-S2 無線鏈路，保留為備用）傳回地面站電腦。地面站顯示文字訊息與狀態、手機清單、被選手機的即時縮圖，儲存所有資料與時間點、嚴重時顯示影像，並可選手機、輸入文字經同一條連線傳回 Jetson。之後可能有多台 Jetson 接進來。

```
多支手機瀏覽器 ──Wi-Fi 熱點 / HTTPS──▶ Jetson Orin Nano（node_id）
                                    │ 每 5 秒輪流取一支手機的影格
                                    ├─ YOLO26s（TensorRT FP16）→ 物件清單 ＋ 規則判定
                                    ├─ Qwen3-VL 2B（Ollama，預填空 think）← 影像 ＋ YOLO 物件清單
                                    └─ 融合：取兩者中較嚴重者 → 一般 / 警告 / 嚴重
                                    │
                                    │ RJ45 → OneWeb 終端 → 衛星 → 網際網路：一條 TCP 連線，Nano 主動連到地面站 123.193.37.73:6767
                                    ├──▶ 報告、嚴重時附影像、心跳含手機清單、縮圖每秒 1 張
                                    ◀──┤ 選手機、開始/停止偵測、設定、文字通知（Jetson 回 ACK）
                                    │
                                地面站電腦（路由器轉發 TCP 6767）：儀表板（手機面板、縮圖、鏈路面板）、SQLite、影像存檔、CSV 匯出
                                （備用：兩台 USRP B210 的 DVB-S2 無線鏈路，下行 1000 MHz 8PSK 2/3、上行 1050 MHz QPSK 1/2）
```

## 2. 關鍵設計決策

| 項目 | 決定 | 原因 |
|---|---|---|
| 手機影像 | 瀏覽器開 `https://10.42.0.1:8443/camera`，輸入名稱，不裝 App | Android、iPhone 都能用；瀏覽器只允許在 HTTPS 頁面開相機，所以用自簽憑證 |
| 多支手機 | 每支手機一個 id（瀏覽器記住）＋名稱；Jetson 輪流辨識「最久沒被辨識且有新影格」的那支 | 使用者決定「輪流全做」；N 支手機每支約 N×5 秒一筆 |
| 選手機 | 地面站 SELECT（含 id、boot）→ Jetson 回 SELECT_ACK，沒回每 3 秒重送最多 10 次 | 和通知同一套可靠機制；第一支連上的手機自動選中 |
| 縮圖 | **預設每秒 1 張、320 px，VLM 影像 448 px**；地面站儀表板可調（縮圖 0–3 張/秒、大小、VLM 320/448/640），走 SELECT 有 ACK | 原本 3 張/秒、480 px、VLM 640 px 讓 Nano 記憶體只剩 200 MB、數據機欠載，改成預設低、可手動調高 |
| 物件偵測 | YOLO26s，TensorRT FP16 | 不需要 NMS，適合 Jetson；FP16 幾乎不掉精度 |
| 場景判讀 | Qwen3-VL 2B，透過 Ollama，**`mode: prefill`**（assistant 預填空的 `<think></think>`），解析時逐一嘗試每個 `{…}` | 這個模型是 thinking 版（`ollama show` 的 renderer 為 qwen3-vl-thinking）；`think: false`、`/no_think` 實測都擋不住思考，token 用完後 content 為空、全部變成「模型輸出無法解析」。預填法三張圖全部成功，約 60 個 token |
| 融合規則 | 最終狀態 = max(VLM 判定, YOLO 規則判定) | 寧可多報不要漏報 |
| **鏈路（10-27）** | **OneWeb 衛星上網，`link.mode: tcp`**：Nano 當 TCP client 主動連到地面站對外位址，地面站當 server（可接多台）；TS 位元流直接走 TCP | OneWeb 終端在 CGNAT 後面不能被連入，只能由 Nano 發起；TCP 可靠、有流量控制，不必重送與節流；一條連線雙向，地面站不用知道 Nano 的 IP |
| 地面站可被連到 | 路由器把 TCP 6767 轉發到筆電（對外 123.193.37.73），`ufw allow 6767/tcp` | 使用者已設；改用 Tailscale 也可（兩邊裝、`connect` 填 100.x.x.x），還能遠端 SSH 進 Nano |
| 斷線偵測 | TCP keepalive 10 s／5 s×3 ＋ `TCP_USER_TIMEOUT` 20 s；斷線 3 秒重連、連不上 5 秒重試 | 不設的話 Linux 預設要十幾分鐘才發現對方消失 |
| **DVB-S2（備用）** | **FPGA 數據機**：dvb-s2-sdr 專案的 `dvbs2_b210`＋自製 B210 image，`link.mode: fpga` | 2026-10-25 兩台實機全雙工 UDP 驗證通過；gr-dvbs2rx 軟體路線從未在實機跑過，改為保留不用 |
| 頻率／MODCOD | 下行 1000 MHz 8PSK 2/3 增益 70；上行 1050 MHz QPSK 1/2 增益 80 | 兩台之間 TX 增益 40 收不到；上行方向餘裕小，8PSK 2/3 解不出，指令量小用 QPSK 1/2 最穩 |
| 多台 Jetson | 所有訊息帶 `node.id`，地面站記錄來源節點 | 使用者決定先做一台；地面站一台 USRP 只能收一個頻道，多台時每台配一台地面站 USRP |
| 傳輸協定 | 訊息切成 MPEG-TS 封包，CRC32 驗證，continuity counter 偵測掉包 | 保留原設計，TCP 與 DVB-S2 共用；tcp 模式地面站每條連線一個解多工器 |

## 5. 已知風險

- **記憶體 OOM（已發生兩次：12:05、13:45）**：核心把 Ollama 的 llama-server 砍掉（RSS 5.8 GB；Jetson 的 GPU 記憶體算在行程裡），當時程式與另一個測試同時對 Ollama 發請求、多個 context 一起吃記憶體；11:42 的重開機很可能同一原因。
  程式本身一次只發一個 VLM 請求（busy 旗標），不要另外同時跑測試。`vlm.num_ctx` 已降到 3072；**建議在 `/etc/systemd/system/ollama.service.d/wait-gpu.conf` 的 [Service] 加 `Environment=OLLAMA_NUM_PARALLEL=1`**（預設可能開多個 slot，每個都配 KV cache），再 `sudo systemctl daemon-reload && sudo systemctl restart ollama`；關桌面省 0.8 GB。Ollama 被砍後會自動重啟，程式下一次請求就恢復。

- Jetson 跑 YOLO＋VLM 時 CPU 很滿，`dvbs2_b210` 排不到時間會 USB 欠載，造成對方漏幀（實測 2.5 分鐘 10 次、掉 3 個縮圖封包）。先做 usrp 群組；仍不夠時降低 `thumb_fps` 或符號率。
- **OneWeb／網路**：地面站對外 IP 由電信業者配發，變了 Nano 就連不上（要改 `link.tcp.connect`，或改用 Tailscale）；路由器重設會掉轉發規則；OneWeb 終端被遮或天氣差時 RTT 升高、TCP 重傳增加，程式會自動重連，期間報告排隊、心跳可能丟棄。
- 多台 Nano 同時連入時鏈路層已支援，但儀表板即時狀態（手機清單、設定、選擇）仍只顯示最後一個心跳的節點。
- （備用鏈路）上行（地面站 → Jetson）Es/N0 只有約 9 dB，天線位置稍差就掉；已改 QPSK 1/2 ＋增益 80，餘裕約 8 dB。DVB-S2 沒有重傳：報告只送一次；嚴重事件重送 2 次並去重。
- `common/ts.py` 的 TS 分段在 UDP 封包各自成框的鏈路上是多一層保險，可以考慮之後移除以降低延遲。

```bash

      --exclude '*.pt' --exclude '*.onnx' --exclude '*.engine' --exclude __pycache__ ~/fieldlink/ lab602@192.168.55.1:~/fieldlink/

# Jetson 程式（正式：tcp 模式，連到地面站對外位址；或 ./tools/restart_jetson.sh）

# Jetson 程式（備用：USRP DVB-S2）
cd ~/fieldlink && .venv/bin/python jetson/app.py --link-mode fpga

# 地面站程式（筆電）
```
