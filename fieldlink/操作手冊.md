# 場域監測系統 操作手冊（Jetson Orin Nano 現場節點 ＋ 地面站電腦）

最後更新：2026-10-27。對應程式版本：fieldlink（本資料夾）。鏈路：**OneWeb 衛星網路（TCP，`link.mode: tcp`）**；USRP／DVB-S2 無線鏈路保留為備用（§10）。

```
手機 ×N ──Wi-Fi 熱點 JetsonCam──▶ Jetson Orin Nano ──乙太網路──▶ OneWeb 終端 ~~~ 衛星／網際網路 ~~~ 路由器（TCP 6767 轉發）──▶ 地面站電腦
   瀏覽器相機頁                    YOLO + VLM 辨識            一條 TCP 連線，由 Nano 主動連到 123.193.37.73:6767            儀表板 http://localhost:8080
                                                            Nano → 地面站：報告、縮圖、心跳　　地面站 → Nano：開始/停止偵測、選手機、通知
```

| 角色 | 機器 | 帳號／位址 |
|---|---|---|
| 現場節點 | Jetson Orin Nano（`~/fieldlink`） | 帳號 `lab602`；USB-C 連電腦時 `192.168.55.1`；熱點內 `10.42.0.1` |
| 現場上網 | OneWeb 使用者終端 | 乙太網路線接 Nano 的 RJ45 孔（Nano 的 Wi-Fi 要留給熱點）；終端在 NAT 後面、不能被連入 |
| 地面站 | 筆電（`~/fieldlink`），區網 192.168.0.80 | 儀表板 `http://localhost:8080`；TCP 6767 等 Nano 連入 |
| 地面站對外 | 路由器（一般網路） | 對外 IP `123.193.37.73`，已把 TCP 6767 轉發到筆電 |
| 備用無線鏈路 | 兩台 NI USRP-2901（B210） | 不接 OneWeb 時改 `link.mode: fpga`，見 §10 |
| 手機 | 任何有瀏覽器的手機 | 連 Wi-Fi `JetsonCam`，開 `https://10.42.0.1:8443/camera` |

## 1. 硬體接線

**Jetson Orin Nano**

1. 19 V 電源接 DC 圓孔。
2. OneWeb 使用者終端的乙太網路（LAN）接 Nano 的 RJ45 孔；終端照原廠方式上電、對準衛星。Nano 內建 Wi-Fi 是熱點 JetsonCam 用的，**上網一定走有線**。
3. 維護用：USB-C 線接電腦（會出現 192.168.55.x 網路），或接 DisplayPort 螢幕＋鍵盤。
4. microSD 卡（系統在裡面）不要拔。USRP 不用接。

**地面站電腦**

1. 接一般網路（有線或 Wi-Fi 都可），能上網即可，不需要 USRP。
2. 路由器要把 **TCP 6767** 轉發到這台電腦（目前已設：對外 `123.193.37.73:6767` → `192.168.0.80:6767`）。
3. 電腦防火牆放行一次：`sudo ufw allow 6767/tcp`。

**網路怎麼接通**：OneWeb 終端在電信業者的 NAT 後面，沒有公網 IP、不能被連入，所以是 **Nano 主動連到地面站**，地面站必須能被連到（路由器轉發，或兩邊都裝 Tailscale）。
連上之後兩個方向都走同一條 TCP 連線，地面站不需要知道 Nano 的 IP。對外 IP 若被電信業者更換，改 Nano 的 `config/jetson.yaml` → `link.tcp.connect`。

## 2. 每日啟動順序（依序做）

1. **啟動地面站**（電腦，先開；Nano 連不上時每幾秒會自己重試，順序反了也沒關係）：
   ```bash
   ~/fieldlink/tools/restart_ground.sh
   ```
   瀏覽器開 `http://localhost:8080`。「資料鏈路：OneWeb 衛星網路（TCP）」面板此時顯示「等待 Jetson 連入」。
2. **OneWeb 終端上電**並等它連上衛星（終端指示燈／App 顯示上線）。
3. **Nano 上電**，等 1 到 2 分鐘。從電腦確認它起來了、而且能上網（USB-C 連著時）：
   ```bash
   ping -c 1 192.168.55.1 && ssh lab602@192.168.55.1 'systemctl is-active ollama; nmcli -t -f DEVICE,STATE device status | grep -E "wlP1p1s0|eth"; ping -c 1 -W 3 123.193.37.73 >/dev/null && echo 網路OK'
   ```
   期望：`active`、`wlP1p1s0:connected`（熱點已開）、有線網路 `connected`、`網路OK`。**電腦沒有接 USB-C 線時**，改用 §3.1.1 的方式之一（最簡單：電腦 Wi-Fi 先連 JetsonCam，把下面所有 `192.168.55.1` 換成 `10.42.0.1`）。
4. **啟動 Nano 程式**（電腦端一行完成，或在 Nano 上執行 `~/fieldlink/tools/restart_jetson.sh`）：
   ```bash
   ssh lab602@192.168.55.1 '~/fieldlink/tools/restart_jetson.sh'      # 沒接 USB-C：ssh lab602@10.42.0.1 '...'
   ```
   看到 `jetson/app.py 已啟動` 即可；它會連到地面站、載入 YOLO（約 10 秒）和 VLM。
5. **確認鏈路**：儀表板右上角膠囊變綠「現場節點 1 連線中，N 秒前收到心跳」；「資料鏈路」面板變成綠色 **已連線**、有 RTT（OneWeb 實測約 300 ms）。通常 Nano 程式啟動後 10 秒內。
6. **手機連線**：手機 Wi-Fi 連 `JetsonCam`，瀏覽器開 `https://10.42.0.1:8443/camera`，接受自簽憑證警告（進階 → 繼續前往），輸入這支手機的名稱（例如「A 區大門」），按「開啟相機並開始傳送」。儀表板「手機」面板幾秒內出現它。
7. **開始辨識**：儀表板橫幅左側按綠色「**開始偵測**」。沒按之前 Jetson 只收畫面、送縮圖，不會出報告。

## 3. Nano 端操作

### 3.1 怎麼連進去

| 方式 | 做法 |
|---|---|
| 從電腦 SSH（建議） | USB-C 線接著：`ssh lab602@192.168.55.1`（這台筆電已裝金鑰免密碼）；或電腦連熱點 JetsonCam 後 `ssh lab602@10.42.0.1` |
| 螢幕鍵盤 | DisplayPort 螢幕；若已關桌面則是文字登入 |
| 監控網頁 | 電腦瀏覽器開 `https://192.168.55.1:8443/monitor`（接受憑證）：手機清單、被選手機畫面、系統狀態、地面站通知 |

### 3.1.1 電腦沒有接 USB-C 線時（Nano 獨立運作）

USB-C 線只是維護用，**沒有它整個系統照常運作**：手機走熱點、報告走 OneWeb 網路，地面站儀表板上的「開始偵測」「選手機」「通知」也都是經同一條 TCP 連線送到 Nano。
只有「在 Nano 上打指令」（啟動程式、看 log、關機）需要下面三種方式之一：

**方式 A：電腦連 Nano 的熱點，再 SSH**（最常用）

1. 電腦的 Wi-Fi 連 `JetsonCam`（和手機用同一個密碼）。電腦連上熱點後不能同時用這張 Wi-Fi 上網，有線網路不受影響。
2. 之後所有指令把 `192.168.55.1` 換成 `10.42.0.1`：
   ```bash
   ssh lab602@10.42.0.1 '~/fieldlink/tools/restart_jetson.sh'            # 啟動
   ssh lab602@10.42.0.1 'grep TCP ~/fieldlink/logs/jetson_app.log | tail -n 3'   # 看鏈路（已連上／中斷）
   ssh lab602@10.42.0.1 'curl -sk https://127.0.0.1:8443/api/state | python3 -m json.tool | head -30'   # 狀態
   ssh lab602@10.42.0.1 '~/fieldlink/tools/stop_jetson.sh && sudo poweroff'   # 關機
   ```
   這台筆電已裝 SSH 金鑰，走熱點一樣免密碼；換另一台電腦會問 lab602 的密碼。
3. 監控頁：`https://10.42.0.1:8443/monitor`（接受憑證）。

**方式 B：Nano 接螢幕鍵盤，直接在本機打**

1. 接 DisplayPort 螢幕與 USB 鍵盤（若已關桌面，是文字登入畫面；輸入 `lab602` 與密碼）。
2. 指令和 SSH 進去後一模一樣，只是前面不用 `ssh ...`：
   ```bash
   cd ~/fieldlink
   ./tools/restart_jetson.sh                       # 啟動（或重啟）
   ./tools/stop_jetson.sh                          # 停止
   tail -f logs/jetson_app.log                     # 看辨識 log，Ctrl-C 離開
   grep TCP logs/jetson_app.log | tail -n 3        # 鏈路：「TCP 已連上地面站」／「TCP 鏈路中斷」
   ping -c 1 123.193.37.73                         # OneWeb 有沒有通到地面站那邊
   curl -sk https://127.0.0.1:8443/api/state | python3 -m json.tool | head -30
   nmcli -t -f DEVICE,STATE device status | grep wlP1p1s0     # 熱點有沒有開（connected）
   iw dev wlP1p1s0 station dump | grep -c Station             # 幾支手機連著
   systemctl is-active ollama                                  # VLM 服務
   free -m                                                     # 記憶體
   sudo poweroff                                               # 關機
   ```
3. 想在前景看程式輸出：`cd ~/fieldlink && .venv/bin/python jetson/app.py`，Ctrl-C 停止；離開前要重新用 `restart_jetson.sh` 以背景方式啟動，否則登出就停了。

**方式 C：用手機 SSH**

手機裝 SSH App（Android：Termux、JuiceSSH；iPhone：Termius），連熱點後連 `10.42.0.1`、帳號 `lab602`、輸入密碼，指令同方式 B。適合現場只有手機時啟動或關機。

**方式 D：從地面站經網際網路 SSH（選用，要先裝 Tailscale）**

Nano 在 OneWeb 的 NAT 後面，地面站本來連不進去。若在 Nano 和電腦都裝了 Tailscale（`curl -fsSL https://tailscale.com/install.sh | sh` 後 `sudo tailscale up`，兩台登入同一帳號），
就能在任何地方 `ssh lab602@<Nano 的 100.x.x.x>`，連 `restart_jetson.sh`、看 log 都不用到現場；此時 `link.tcp.connect` 也可以改成地面站的 Tailscale IP，不再依賴路由器轉發。

**沒有任何方式能連進去時**：Nano 上電後程式不會自動啟動，所以一定要有一種方式能下 `restart_jetson.sh`。若希望上電即自動啟動（連 SSH 都不用），請設定 §3.8 的開機自動啟動。

### 3.2 啟動、停止、重啟程式

```bash
cd ~/fieldlink
./tools/restart_jetson.sh      # 停掉舊的、用 nohup 啟動新的，log 在 logs/jetson_app.log
./tools/stop_jetson.sh         # 停止程式
```

手動啟動（想在前景看輸出時）：`cd ~/fieldlink && .venv/bin/python jetson/app.py`，Ctrl-C 停止。
改走 USRP 無線鏈路：`--link-mode fpga`（§10）；開發用：`--link-mode udp`。

程式**不會開機自動啟動**，每次 Nano 重開後都要執行一次 `restart_jetson.sh`。重啟後「偵測」會回到停止狀態，要在地面站再按一次「開始偵測」。

### 3.3 檢查狀態

```bash
pgrep -af "jetson/app[.]py"                           # 程式有沒有在跑
curl -sk https://127.0.0.1:8443/api/state | python3 -m json.tool | head -40   # 手機清單、偵測狀態、鏈路（"link" 區塊）
tail -f ~/fieldlink/logs/jetson_app.log               # 程式 log：辨識結果、通知、錯誤、鏈路連上／中斷
grep TCP ~/fieldlink/logs/jetson_app.log | tail -n 5   # 只看鏈路
nc -zv -w 5 123.193.37.73 6767                        # 從 Nano 測地面站的埠通不通（succeeded = 通）
ip route get 123.193.37.73                            # 要看到 dev enP8p1s0（OneWeb 終端的有線），不是 l4tbr0／wlP1p1s0
ss -tni "dst 123.193.37.73"                           # 這條 TCP 連線與 rtt（OneWeb 約 300 ms）
for t in $(seq 1 25); do ping -n -t $t -c 1 -W 2 123.193.37.73 2>&1 | grep -E "^From|bytes from" | sed "s/^/$t: /"; done   # 逐跳路徑（沒裝 traceroute 時）
```

2026-10-27 量到的路徑：終端 192.168.100.1 → 衛星 → OneWeb 閘道 10.82.250.193 → 中華電信國際閘道 TWGate → 洛杉磯 → Arelion → PCCW → 台灣固網 → 凱擘 → 123.193.37.73，共 20 跳；衛星段約 120 ms，其餘繞美西。

鏈路 log 怎麼看：

```
TCP 已連上地面站 123.193.37.73:6767                   正常
TCP 連線結束 123.193.37.73:6767：對方關閉             地面站程式停了，3 秒後自動重連
TCP 連線結束 ...：[Errno 110] Connection timed out     送出 20 秒沒 ACK：OneWeb 斷了或 NAT 映射失效，自動重連
鏈路啟動失敗：[Errno 111] Connection refused（5 秒後重試）   地面站埠沒開（程式沒跑、防火牆、路由器沒轉發）
```

`/api/state` 的 `link`：`connected`（已連上）、`peer`、`rtt_ms`（往返延遲）、`retrans`（TCP 重傳累計，持續增加表示網路差）、`restarts`（重連次數）。
Nano 的監控頁（§3.1）也顯示同一資訊。

### 3.4 設定檔 `config/jetson.yaml`（改完要 `restart_jetson.sh`）

| 區段 | 重點 |
|---|---|
| `node.id`、`node.name` | 這台 Jetson 的代號與名稱，多台時要不同 |
| `capture.detect` | 開機後是否立刻辨識：0 等地面站按開始（預設），1 一開機就辨識 |
| `capture.interval_s` | 幾秒取一支手機辨識一次（5） |
| `capture.thumb_fps`、`thumb_max_side` | 縮圖預設值（1 張/秒、320 px）；地面站可隨時改 |
| `capture.vlm_max_side` | 送進 VLM 的影像大小（448）；越大越慢越吃記憶體 |
| `capture.image_on` | 哪些等級要附影像（預設只有 critical） |
| `vlm.model`、`vlm.mode`、`vlm.num_ctx` | 模型 `qwen3-vl:2b`；`mode: prefill` 是給 thinking 版模型用的（不要改）；`num_ctx` 3072 |
| `vlm.rules` | 一般／警告／嚴重的判斷準則，**依場域改寫這段最有效** |
| `yolo.model`、`fusion.rules` | 偵測模型與「偵測到什麼就直接升級」規則；預設 COCO 模型沒有火／煙類別 |
| `link.mode` | `tcp`（OneWeb／網路，預設）、`fpga`（USRP 無線，備用）、`udp`（開發） |
| `link.tcp.connect` | 地面站的對外位址 `123.193.37.73:6767`；對外 IP 換了或改用 Tailscale 時改這裡 |
| `link.tcp.timeout_s` | 送出多久沒 ACK 判定斷線並重連（20 秒） |
| `link.fpga`（備用） | 數據機：`tx_freq` 1000 MHz、`rx_freq` 1050 MHz、`modcod` 13（8PSK 2/3）、`tx_gain` 70、`rx_gain` 40、程式與 image 路徑 |

### 3.5 Wi-Fi 熱點

已設定好：連線名 `jetson-hotspot`，SSID `JetsonCam`，5 GHz，Nano 位址 `10.42.0.1`，開機自動啟動。

```bash
nmcli -t -f DEVICE,STATE device status | grep wlP1p1s0       # connected = 熱點開著
iw dev wlP1p1s0 station dump | grep -c Station                # 連著幾支手機
sudo ./jetson/setup_hotspot.sh JetsonCam 新密碼 wlP1p1s0            # 改密碼（重設整個熱點）
BAND=bg sudo ./jetson/setup_hotspot.sh JetsonCam 密碼 wlP1p1s0      # 手機搜不到 5 GHz 時改 2.4 GHz
```

熱點佔用 Nano 的 Wi-Fi，所以上網（OneWeb）走有線 RJ45；更新套件也走同一條有線網路。

### 3.6 AI 模型與 Ollama

```bash
ollama ps                         # VLM 是否在記憶體裡，PROCESSOR 應為 100% GPU
systemctl status ollama           # 服務狀態；被記憶體不足砍掉時會自動重啟，程式下一次請求就恢復
ls ~/fieldlink/models             # yolo26s.engine（第一次執行時自動產生，升級 JetPack 後刪掉重產）
```

`/etc/systemd/system/ollama.service.d/wait-gpu.conf` 已加 `Environment=OLLAMA_NUM_PARALLEL=1`（避免多個 context 吃光記憶體）。

### 3.7 建議做一次的系統設定（需要 sudo）

```bash
sudo usermod -aG usrp lab602                # 讓 USRP 程式拿到即時優先權，消除 USB 欠載（重新登入生效）
sudo systemctl set-default multi-user.target   # 關掉桌面省約 0.8 GB 記憶體（重開機生效）；要恢復改 graphical.target
```

### 3.8 選用：開機自動啟動（之後完全不必下指令）

在 Nano 上執行一次（需要 sudo）：

```bash
sudo tee /etc/systemd/system/fieldlink-jetson.service >/dev/null <<'UNIT'
[Unit]
Description=fieldlink field node (Jetson)
After=network-online.target ollama.service
Wants=network-online.target

[Service]
Type=simple
User=lab602
WorkingDirectory=/home/lab602/fieldlink
ExecStart=/home/lab602/fieldlink/.venv/bin/python jetson/app.py
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
UNIT
sudo systemctl daemon-reload && sudo systemctl enable --now fieldlink-jetson
```

之後：`systemctl status fieldlink-jetson`（狀態）、`sudo systemctl restart fieldlink-jetson`（重啟）、`journalctl -u fieldlink-jetson -f`（看 log）、`sudo systemctl disable --now fieldlink-jetson`（取消）。
啟用後請不要再用 `restart_jetson.sh`，兩者會互搶 USRP 與 8443 埠。偵測開關仍由地面站控制（開機後是停止）。

### 3.9 關機

```bash
~/fieldlink/tools/stop_jetson.sh && sudo poweroff
```

直接拔電也可以，但建議先 `poweroff`（microSD 比較不會壞）。

## 4. 地面站（電腦）操作

### 4.1 啟動、停止

```bash
cd ~/fieldlink
./tools/restart_ground.sh      # 啟動：儀表板 8080、TCP server 6767 等 Nano 連入；log 在 logs/ground_app.log
./tools/stop_ground.sh         # 停止
```

第一次要做：`sudo ufw allow 6767/tcp`（防火牆放行），路由器把 TCP 6767 轉發到這台（已設）。
自我檢查埠有沒有通：`nc -zv -w 5 123.193.37.73 6767` 印 `succeeded`，而且 `logs/ground_app.log` 多一行 `TCP 連線建立`。
前景執行：`.venv/bin/python ground/app.py`。儀表板 `http://localhost:8080`；要給同網路的其他電腦看，把 `config/ground.yaml` 的 `web.host` 保持 `0.0.0.0` 並用這台的 IP 開（沒有密碼，只在可信網路用）。

### 4.2 儀表板怎麼用

**頂部列**：分頁（主畫面／紀錄／通知會捲到該區）、連線膠囊（綠＝收到 Jetson 心跳、紅＝中斷、灰＝等待）、右上角時鐘（本地＋UTC）。

**狀態橫幅**（最新一筆報告的等級與手機；嚴重＝紅、警告＝橘、一般＝綠）：

| 按鈕 | 作用 |
|---|---|
| **開始偵測 / 停止偵測** | 叫 Jetson 開始或停止對影像做 YOLO＋VLM 辨識。只影響辨識，手機畫面與縮圖照常。按下後顯示「等待 Jetson 確認…」，Jetson 回 ACK 才變色。Nano 重啟後會回到停止 |
| **看影像** | 捲到最新的嚴重事件影像（只有有嚴重事件時出現） |
| **清空** | 把目前為止的報告從儀表板移除：橫幅與目前狀態回到「已清除」、最近 30 分鐘統計與時間軸歸零、嚴重事件影像收起。紀錄表與資料庫不刪，之後只累計新報告。重整或重啟都記得 |
| **送通知到 Jetson** | 捲到通知區 |

**目前狀態**：大字等級、描述、截圖與收到時間、VLM／YOLO 耗時；指標卡：最近一次 VLM 秒數、30 分鐘內一般／警告／嚴重筆數、最近兩筆報告間隔。膠囊顯示「偵測中」或「偵測已停止」。

**手機**：每支手機一列（綠點＝有畫面、黃點＝連著但沒畫面、灰＝離線；右邊是它最新一筆的等級與已辨識次數）。
「**看這支**」＝叫 Jetson 回傳這支手機的即時縮圖（有 ACK）。下方三個下拉選單即時調整：縮圖頻率（不送～每秒 3 張）、縮圖大小（240～640 px）、VLM 影像（320／448／640 px；越大越準但越慢、越吃 Nano 記憶體）。

**即時縮圖**：被選手機的畫面，標題旁是實際收到的張數／秒；指標卡顯示速率與每張大小。

**資料鏈路：OneWeb 衛星網路（TCP）**（`link.mode: tcp` 時）：

| 項目 | 意義 |
|---|---|
| 已連線／等待 Jetson 連入 | Nano 有沒有連進來；「地面站 server · N 台 Jetson」是目前連著幾台 |
| RTT | TCP 往返延遲；OneWeb 實測約 300 ms（指令來回約 0.4 秒），超過 1.5 秒變黃 |
| 對方位址 | 看到的是路由器轉來的位址與連線多久 |
| TCP 重傳 | 累計；偶爾幾次正常，持續增加表示衛星鏈路品質差 |
| 收到／送出、重新連線 | 資料量與訊息數；重連次數增加表示 OneWeb 曾斷線（程式會自動接回） |
| Jetson 端 | Nano 心跳回報的它那邊的連線與 RTT |

**DVB-S2 接收（下行）**（`link.mode: fpga` 時，同一個面板）：

| 項目 | 意義 |
|---|---|
| LOCK／未鎖定、MODCOD、導頻、FLL | 本機數據機有沒有鎖定 Jetson 的訊號；MODCOD 顯示「DUMMY」表示最近一幀是對方沒資料時的填充幀，正常 |
| Es/N0 | 訊號雜訊比（盲估計）。≥ 10 dB 綠、7–10 黃、更低紅；8PSK 2/3 大約 7 dB 以下就解不出 |
| 解碼率 | 實際收到的資料率 / 容量；對方沒送多少東西時很低是正常的 |
| 頻率偏移 | 兩台振盪器差；約 2 kHz（2 ppm）正常 |
| 訊號電平 | dBFS；高於 −3 會提示飽和，請降對方發射增益 |
| 幀數／漏幀、LDPC、BCH 失敗／CRC、USB 溢位 | 累計計數；漏幀與 USB 數字持續增加代表 Nano 太忙或訊號太弱 |
| 頻譜圖、瀑布圖 | 1024 點 FFT，dB 範圍可改；訊號應該是中央約 2 MHz 寬的平台，兩側是雜訊底 |

**鏈路與上行**：fpga 模式時 Jetson 端收上行的鎖定、Es/N0、頻偏、漏幀；tcp 模式只顯示地面站收到幾則訊息、CRC 錯幾次。

**最近 30 分鐘**：時間軸，每筆報告一條（高度＝等級）；標題旁是計數。**嚴重事件影像**：最新一筆嚴重報告附的影像，畫面上有偵測框（每個類別固定一色，外框紅＝嚴重）。
**通知**：輸入最多 200 字送到 Jetson（Jetson 螢幕與所有手機頁會跳出），沒收到 ACK 會每 6 秒重送最多 5 次。
**辨識紀錄**：全部報告，可依等級篩選、「看影像」、右上角「匯出 CSV」（Excel 可直接開，含節點、手機、VLM／YOLO 判定欄位）。

## 7. 排障

| 現象 | 原因與處理 |
|---|---|
| 儀表板「等待 Jetson 連入」超過 1 分鐘 | 依序查：① Nano 程式沒跑（`pgrep -af "jetson/app[.]py"`）② Nano 沒網路（在 Nano `ping -c 1 123.193.37.73`；OneWeb 終端上線了嗎、RJ45 接了嗎）③ 地面站埠不通（在 Nano `nc -zv -w 5 123.193.37.73 6767`；地面站 `ss -ltn \| grep 6767`、`sudo ufw status`、路由器轉發）④ 對外 IP 變了（地面站 `curl -s https://api.ipify.org` 和 `jetson.yaml` 的 `connect` 比對） |
| Nano log「Connection refused」 | 地面站程式沒跑或埠沒轉發到它；「Connection timed out」則是 Nano 根本到不了地面站（OneWeb 斷、路由器丟包） |
| 已連線但 RTT 很高、TCP 重傳一直增加、縮圖變慢 | OneWeb 鏈路品質差（終端被遮、天氣）；先把縮圖降到每秒 1 張／不送，報告仍會送達（TCP 不丟） |
| 「重新連線」次數一直增加 | OneWeb 每隔一陣子斷線；程式會自己接回，期間的報告會排隊等重連後送出（心跳可能丟棄） |
| 「本機 DVB-S2 程式無法啟動」（fpga 模式） | 地面站找不到 USRP（`uhd_find_devices`）、USB 線鬆、image 路徑錯、或另一個 `dvbs2_b210` 還在（`pkill -x dvbs2_b210`）；看 `logs/dvbs2_b210.log` |
| 數據機 log 一直 `----`、Es/N0 低、`host U`（fpga 模式） | 見 §10 |
| 報告寫「VLM 推論失敗：Cannot connect to host 127.0.0.1:11434」 | Ollama 被記憶體不足砍掉，約 30 秒內自動重啟、程式自動恢復。常發生就關桌面、`vlm_max_side` 用 320／448、不要同時在 Nano 上跑別的 |
| 報告寫「模型輸出無法解析」 | 模型沒照格式回答；偶發可忽略，頻繁時換模型或縮短 `vlm.rules` |
| 誤判（例如正常畫面判警告） | 改寫 `vlm.rules` 讓準則更貼近場域；把 VLM 影像調到 448 或 640；訓練專用 YOLO 並設 `fusion.rules` |
| 手機頁開不了相機 | 一定要 https 且已接受憑證；iPhone 用 Safari、Android 用 Chrome |
| 手機搜不到 JetsonCam | 手機不支援 5 GHz：改 2.4 GHz（§3.5） |
| 清空後舊資料不見 | 只是儀表板不顯示；辨識紀錄表與 CSV 都還在 |
| Nano 重開後沒有任何東西 | 程式不會自動啟動，執行 `restart_jetson.sh`；偵測回到停止，要再按「開始偵測」 |
| 電腦 ping 不到 192.168.55.1 | USB-C 線兩端重插；Nano 開機要 1 到 2 分鐘；若 Nano 卡死（通常是記憶體耗盡）斷電重開 |
| 電腦沒接 USB-C，要怎麼下指令 | 電腦 Wi-Fi 連 JetsonCam 後 `ssh lab602@10.42.0.1`，或 Nano 接螢幕鍵盤本機操作，或手機 SSH，或兩邊裝 Tailscale 經網路 SSH（§3.1.1）；儀表板上的操作本來就走 OneWeb 鏈路，不需要連線 |

## 10. 備用：USRP／DVB-S2 無線鏈路（`link.mode: fpga`）

沒有 OneWeb 或網路時，可改回自建的 DVB-S2 無線鏈路。兩邊 `config/*.yaml` 的 `link.mode` 改成 `fpga`（或啟動時加 `--link-mode fpga`），再 `restart_*.sh`。

**接線**：Nano 的 USB 3（藍色）孔接 USRP（NI USRP-2901 序號 32B8759）；天線 **TX/RX A**（發射，下行 1000 MHz）、**RX2 A**（接收，上行 1050 MHz），B 側不用。
地面站電腦接另一台 USRP（序號 30FB57D）：**TX/RX A**（發射上行 1050 MHz）、**RX2 A**（接收下行 1000 MHz）。

**參數**：下行 8PSK 2/3（約 2.5 Mbit/s）增益 70，上行 QPSK 1/2（約 1.2 Mbit/s）增益 80，兩邊 RX 增益 40，2 MHz 頻寬、roll-off 0.35；
`link.fpga.tx_freq` 必須等於對方的 `rx_freq`。同一房間數公尺 Es/N0 約 19 dB；靠太近（< 1 m）電平超過 −3 dBFS 會飽和，請降對方 TX 增益；TX 增益 40 完全收不到。
空中傳輸須符合 NCC 規範。

**檢查**：`pgrep -a dvbs2_b210`；兩邊 `tail -f logs/dvbs2_b210.log`（每秒 TX、RX 各一行）：

```
RX LOCK 8PSK 2/3 pil FLL3 CFO -1990.0 Hz | frames 8908 miss 0 | LDPC it 2 drop 0 | BCH corr 0 fail 0 | BB ok 120 crc 0 | ... udp out 300 pkt ... lost 0, bad CRC 0 | host O 0
TX frames encoded 1661 sent 1661 dummy 134632 | DUC underflow 0 | ... host U 0 ... | udp in 518 pkt ...
```

| 欄位 | 意義 | 正常 |
|---|---|---|
| `LOCK` / `----` | 有沒有鎖定對方訊號 | LOCK |
| `CFO` | 兩台振盪器的頻率差 | 約 ±2 kHz，穩定 |
| `miss` | 漏掉的幀（累計） | 不要一直增加 |
| `LDPC it` | 糾錯迭代次數 | 1–3 好，25 代表解不出 |
| `BB ok` / `crc` | 解出的資料幀 / CRC 錯誤 | crc 0 |
| `host U` / `host O` | USB 欠載 / 溢位（累計） | 0；一直增加表示 Nano 太忙：做 §3.7 的 usrp 群組、關桌面、降低縮圖頻率 |
| `dummy` | 沒資料時送的填充幀 | 很大是正常的 |

**排障**：log 一直 `----`、CFO 亂跳＝沒收到訊號（對方沒發、天線沒接、增益太低）；Es/N0 低、漏幀多、LDPC 25＝太弱或太近飽和；
「本機 DVB-S2 程式無法啟動」＝找不到 USRP（`uhd_find_devices`）、image 路徑錯、或舊的 `dvbs2_b210` 還在（`pkill -x dvbs2_b210`）。
儀表板此時的「DVB-S2 接收」面板與「鏈路與上行」面板見 §4.2。多台 Jetson 時每台要配一台地面站 USRP、各用自己的頻率對（tcp 模式則不需要）。

數據機（`dvbs2_b210`）與 FPGA image 的來源是 dvb-s2-sdr 專案（筆電 `~/dvb-s2-sdr`，`b210/README.md`）；RTL 改動後要重編 image（ISE 14.7，約 45 分鐘）並重新放到兩邊的 `out/`。
