# 場域災害偵測系統 簡要說明

## 一、目的

在沒有網路基礎建設的現場，用一般手機當攝影機，由現場的 Jetson Orin Nano 以 AI 即時判讀畫面有無災害徵兆（火、煙、淹水、人員倒地等），
分成「一般／警告／嚴重」三級，再透過自建的 DVB-S2 無線鏈路把判讀結果、縮圖與嚴重事件影像傳回地面站；地面站可反向下指令與通知。
整條路徑不依賴網際網路、基地台或衛星服務。

## 二、災害偵測流程

```
手機瀏覽器（相機頁） ──Wi-Fi 熱點──▶ Jetson Orin Nano                                  地面站電腦
  每秒約 4 張 JPEG                     │ 每 5 秒輪流取一支手機的最新影格                    │
                                      ├─ ① YOLO26s（TensorRT）：找出人、車、物件、位置（數十毫秒）
                                      ├─ ② Qwen3-VL 2B（Ollama）：看圖＋YOLO 清單，寫一句描述並判等級（約 5 秒）
                                      ├─ ③ 融合：取 VLM 判定與 YOLO 規則中較嚴重者 → 一般／警告／嚴重
                                      └─ ④ 報告（JSON）經 DVB-S2 下行 ──────────────────────▶ 儀表板、SQLite、CSV
                                         嚴重時附上畫了偵測框的影像；被選手機另傳即時縮圖
                                      ◀──────────── 上行：開始/停止偵測、選手機、調參數、文字通知（有 ACK 重送）
```

1. **影像來源**：手機不必裝 App，連上 Jetson 的 Wi-Fi 熱點後用瀏覽器開相機頁，輸入名稱即開始上傳；多支手機同時接入，Jetson 輪流辨識。
2. **物件偵測（YOLO26s）**：TensorRT FP16 引擎，每張數十毫秒，產生物件類別、信心、位置；可換成自行訓練的火／煙／倒地模型，並設定「偵測到即升級」規則。
3. **場景判讀（Qwen3-VL 2B）**：視覺語言模型在 Jetson 本機執行，依設定檔中的三級準則寫出中文描述並判定等級；YOLO 的偵測清單一併放進提示，補強小物件與數量判斷。
4. **融合與回報**：最終等級取兩者較嚴重者（寧可多報）；每筆報告含手機、時間、等級、描述、偵測清單、耗時；嚴重事件附影像（最長邊 640 px、上限 60 kB、重送兩次）。
5. **地面站**：收報告、存資料庫、顯示狀態橫幅／時間軸／紀錄／嚴重事件影像；可選看任一支手機的即時縮圖、開始或停止辨識、調整縮圖與 VLM 解析度、送文字通知到現場（手機與 Jetson 螢幕跳出）。

## 三、硬體架構

完整架構圖（Nano 端／PC 端分欄）：[docs/架構圖.svg](docs/架構圖.svg)（同目錄有 PNG 版可直接貼投影片）。

```
             現場                                                    地面站
┌──────────────────────────────────┐          無線 DVB-S2          ┌──────────────────────────────┐
│ 手機 ×N ─Wi-Fi(5 GHz)─▶ Jetson   │   下行 1000 MHz 8PSK 2/3     │ USRP B210 ─USB 3─ 筆電        │
│  Orin Nano 8 GB                  │ ◀────────────────────────── │  TX/RX A 天線（發上行）        │
│  ├ YOLO + VLM（GPU）             │   上行 1050 MHz QPSK 1/2     │  RX2 A 天線（收下行）          │
│  └ USB 3 ─ USRP B210             │ ──────────────────────────▶ │  儀表板 http://localhost:8080 │
│     TX/RX A 天線（發下行）        │                              │  SQLite／CSV／影像存檔         │
│     RX2 A 天線（收上行）          │                              └──────────────────────────────┘
└──────────────────────────────────┘
```

| 元件 | 規格與角色 |
|---|---|
| Jetson Orin Nano 8 GB（JetPack 7.2.1） | 現場節點：Wi-Fi 熱點（10.42.0.1）、YOLO＋VLM 推論（GPU）、驅動 USRP。記憶體是最緊的資源（模型約 5 GB） |
| USRP B210（NI USRP-2901）×2 | 70 MHz–6 GHz 收發器，各接一台主機。**DVB-S2 數據機完整實作在它的 FPGA 裡**（自製 image：BCH＋LDPC 編解碼、成幀、RRC、同步、AGC、FLL／PLL），主機只收送位元組 |
| 天線 ×4 | 每台 USRP 兩支：TX/RX A 發射、RX2 A 接收，實現全雙工（收發不同頻率） |
| 地面站電腦 | Ubuntu 筆電，跑地面站程式與儀表板；不做 AI |
| 手機 | 任何有瀏覽器的手機，當攝影機 |

**無線鏈路參數**：頻寬 2 MHz（符號率 1.48 Msym/s）、roll-off 0.35、短幀、有導頻。
下行 8PSK 2/3 約 2.5 Mbit/s（報告＋縮圖＋影像綽綽有餘）；上行 QPSK 1/2 約 1.2 Mbit/s（指令量小，用最穩的調變）。
同一房間實測 Es/N0 約 19 dB、零位元錯誤；截圖到地面站顯示約 6–8 秒（主要是 VLM 推論），縮圖延遲約 0.1–0.3 秒。

**軟體層次**（兩端相同）：應用程式 ⇄ 本機 UDP ⇄ `dvbs2_b210`（USRP 控制、UDP 封包成框、狀態／頻譜輸出）⇄ USB ⇄ B210 FPGA 數據機 ⇄ 射頻。
訊息以 MPEG-TS 分段並附 CRC32；鏈路無重傳，指令與通知靠應用層 ACK 重送，嚴重事件影像重送兩次並由地面站去重。

## 四、擴充方向

- 多台現場節點：每台 Jetson 有 `node_id`，地面站依節點區分；地面站一台 USRP 一次只能收一個頻道，多節點時每節點配一台地面站 USRP、各用自己的頻率對。
- 專用模型：收集場域影像訓練 YOLO（火、煙、倒地、未戴安全帽），搭配偵測規則可在 VLM 之前直接觸發嚴重等級。
- 更長距離：提高符號率或換高增益天線；目前參數在同一房間有約 12 dB 餘裕。
